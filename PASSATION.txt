 0. RESUME EXECUTIF (lire en 2 minutes)
--------------------------------------------------------------------------------
 MISSION UNIQUE : maximiser le revenu encaisse par jour.

 Deux fonctions, rien d'autre :
   F1 — CHASSEUR-EXECUTEUR : l'agent scanne des sources autorisees, trouve des
        taches faisables par un agent (code, data, R&D, redaction, audit),
        les execute, livre, encaisse (USDC x402 / crypto bounties / fiat).
   F2 — ARBITRAGE HUMAIN   : l'agent trouve une mission exigeant un humain,
        recrute un freelance, encaisse la difference
        (marge = client - freelance - frais - reserve litige - controle).

 Boucle quotidienne : scan (cron 6h) -> scoring -> top-5 propose sur Telegram
 -> validation humaine legere -> execution ou recrutement -> encaissement ->
 rapport KPI chaque soir (20h UTC).

 Garanties dures : plafonds SPEND, matrice ToS enforcee cote serveur, freeze
 immediat, timeout HITL = refus, anti self-dealing, et AUCUN TRADING
 (ni live ni paper — verrouille par tests statiques).

 2.1 STRATEGIE BUSINESS (spec section 1)
   - Ne jamais attendre d'etre achete : l'agent VA CHERCHER des missions payees.
   - F1 d'abord (revenu 100 % autonome sur sources agent-natives x402/Bazaar),
     F2 ensuite (marge sur missions humaines, HITL obligatoire a chaque deal).
   - Seuil de rentabilite F2 : marge nette >= 15 EUR sinon rejet automatique.
   - Reserve litige 10 % sur chaque deal F2.
   - Parite EUR~USDC 1:1 par defaut (parametrable plus tard).

 2.2 STRATEGIE ToS / CONFORMITE (spec section 3)
   - Scanner/partout, soumettre/auto UNIQUEMENT si can_auto_submit = true.
   - Refus par defaut (fail-closed) : plateforme inconnue = refus + HITL.
   - Jamais de contournement anti-bot : si interdit, l'agent prepare le draft
     exact et l'humain clique sur la plateforme.
   - La matrice ne change que par migration SQL revue + test + doc (pas de
     bouton magique). Re-verification trimestrielle visee (last_verified_at).

 2.3 STRATEGIE RISQUE / POLICY (spec section 7)
   - 4 regles, zero exception : plafond SPEND (1 USDC/jour au depart), matrice
     ToS, aucun trading par construction, freeze D1 lu a chaque action sortante.
   - Le LLM PROPOSE, policy.ts DISPOSE. Aucune depense ni soumission interdite
     decidable par le LLM seul.
   - Freeze : /freeze = effet immediat sans redeploiement ; /unfreeze = double
     confirmation (commande + bouton HITL).
   - Timeouts HITL = refus (12 h defaut, 1 h pour unfreeze) ; sans reponse,
     l'agent ne prend rien.

 2.4 STRATEGIE FINANCIERE (spec section 6)
   - PAYTO recoit tout (cle JAMAIS sur serveur) ; OPS = admin symbolique ~2 USDC ;
     SPEND = depenses agent sous plafonds.
   - Anti self-dealing : wallets propres declares (HITL pour ajout), mouvements
     internes requalifies (self_test/transfer), jamais comptes en revenu.
   - Ledger append-only (jamais d'UPDATE financier) + idempotence (nonce/tx
     UNIQUE -> zero double credit).
   - KPI quotidien : Net = Revenu - (fees + paies F2 + couts API), envoye sur
     Telegram + expose via /kpi.
